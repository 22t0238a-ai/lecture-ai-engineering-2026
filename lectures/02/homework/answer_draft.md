## 発展

**取り組んだレベル**: 発展

**変えたデータ**: `scripts/make_sft_dataset.py` で講座の用語集（58 語）から作った Q&A 116 件（1 語あたり言い回し 2 種）で学習した。train 105 件 / valid 11 件。エポック数は合計ステップ数が元の演習と同じ約 40 になるように 3 エポック（約 42 ステップ）にした。答えは JSON ではなく定義文そのもので、「確認が必要」と答える例は 0 件。

**評価用の質問**（15 問。`lectures/02/homework/lora_hw_advanced.ipynb` の `GLOSSARY_EVAL`）

- in 5 問: 学習データと同じ言い回し（例:「「LoRA」とは何ですか？」）。講座固有の語（lecNN-start タグ、既定モデル）を 2 つ含む。
- paraphrase 5 問: 同じ 5 語を、別名や用語名を出さない聞き方で（例:「この講座の演習で標準に使うモデルは何ですか？」）。
- out 5 問: 用語集に無い語。講座固有の架空の語（lecNN-end タグ、評価ハーネス、第4回のテーマ）と、一般には実在するが用語集に無い語（プロンプトキャッシュ、蒸留）。用語集の本文に含まれないことをコードで確かめた。
- 採点: 答えが JSON でないので、形式遵守率は使わず文面で採点した（in / paraphrase は定義文の語句を含むか、out は「記載」「確認」などを含むか）。

予想（結果で確かめて書き直す）:

- 学習のメリット: 推論時に検索が要らず、プロンプトが短い。答え方（形式・口調）がそろう。
- 学習のデメリット:
  - 言い回しを変えると正答率が落ちやすい（in と paraphrase の差で確かめる）。
